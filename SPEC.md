# Tracker Buddy — spec (2026-09-11)

Companion widget for Satva Time Tracker 2.7. Read-only: never writes to the tracker's DB or files.

## Sources
- `(localdb)\MSSQLLocalDB`, DB `Time_Tracker`, table `EmployeeTimeTracker_TimeLog` — one row per start/stop session.
- `C:\Program Files (x86)\Satva\TimeTracker\Persistance_<UserId>.xml` — `UserId`, `TimeLogId`, `Minutes` of the current
  session; rewritten ~every 63 s while running (DB `EndDateTime` is only updated on stop).
- Windows `GetLastInputInfo` — time since last mouse/keyboard input (what the tracker uses for idle).

## Settings (`%LOCALAPPDATA%\TrackerBuddy\settings.json`, gear icon / right-click → Settings…)
- Daily target (default 8:30), default weekly hours (42:30), this week's hours (per-week override, keyed by Monday;
  equal to default → override removed).
- Show/hide shortcut (default Ctrl+Alt+B, global via RegisterHotKey).
- Toggles: idle warning, working-but-tracker-off alert.

## Rules (refresh every 30 s)
- **Running** = newest Persistance file written within the last 2 min.
- **Worked** = Σ today's logs of `max(End − Start, live minutes if log is the persisted one)`. While running, live =
  (now − Start) minus whole minutes of current no-input: persist `Minutes` runs ~1.7% fast (bumped every 59 ticks),
  and on idle stop the tracker sets `End = Start + (seconds − idle seconds)`. Stopped: live = persist `Minutes`.
- **Left** = max(0, daily − Worked). **Finish at** = now + Left (keeps moving while stopped).
- **Idle** = (now − first start today) − Worked, i.e. every gap when the tracker was off.
- **Week** = Σ history rows Mon–Sun vs. this week's required hours (daily target stays fixed).
- **Alerts**: Windows notification once at Left ≤ 15 min, once at Left = 0.

## Live checks (every 5 s)
- **Idle warning**: while running and no input ≥ warn point → sound + notification (once per idle stretch), widget
  turns red "⚠ No input m:ss · stops in ~m:ss". Warn point = 8 min; the tracker's idle limit is hard-coded
  to 10 min (`GetIdleTime() > 600000`) and the whole idle stretch is removed from the log.
- **Tracker off**: not running, input within 30 s, today's target not met → sound + notification; repeats every 10 min.

## Weekly view
- `history.csv` (`date,first_start,last_stop,worked_min,idle_min`), upserted every refresh from the last 7 days in
  the DB. The DB replaces a day while it still has that day's first log (so
  idle corrections flow in); if the first log is gone (DB wiped) only a bigger Worked replaces it.
- Calendar icon / right-click → Week view: Mon–Sun, ± vs daily target, week total vs required and time left.

## UI
Slim pill (310×38, bottom-right, always on top, no focus steal, not in Alt+Tab): status dot, worked, day bar,
finish time, idle. Hover → card grows upward: status, worked of target, finish/left, day bar, week bar, idle,
calendar + gear buttons. Windows 11 rounded corners via DWM. Drag anywhere to move. Tray icon: double-click toggles.
App icon generated by `make-icon.ps1`.

## Sharing & updates
- Public repo `meet09-satva/tracker-buddy`; releases built by `release.ps1 <version>` (self-contained win-x64
  publish → self-test → Velopack `vpk pack` → `vpk upload github`).
- Colleagues install `TrackerBuddyApp-win-Setup.exe` (per-user, no admin, Desktop + Start menu shortcuts).
- Installed copies check GitHub at start and every 6 h; a newer release is downloaded and applied with a restart.
  Right-click → Check for updates. The dev build (`bin\`) never updates.
- Velopack packId `TrackerBuddyApp` ≠ data folder `TrackerBuddy`, so uninstall keeps history and settings.

## Not handled (yet)
Sessions crossing midnight, remembering widget position, browsing older weeks.

## Test
`TrackerBuddy.exe --test` runs assert checks on `Calc`, `History.Merge`, `Settings.WeeklyFor`; exit code 0 = pass.
